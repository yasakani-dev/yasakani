# YASAKANI のモデルファイル形式（`.yskn`）バージョン 1

English: [FORMAT.md](FORMAT.md)

この文書は `.yskn` ファイルの中身をバイト単位で定義します。エンジンを使わずにファイルを読むこと、元の重みと照合すること、ファイルを書くことが、この文書だけでできます。

* この文書だけに従って書いた読み取りプログラム：[`tools/yskn_decode.py`](../tools/yskn_decode.py)（Python と numpy。GPU は不要）
* 小さなテスト用ファイルと、読み取りプログラムが得るべき値：[`tools/testdata/`](../tools/testdata/)
* エンジンの読み取り部分：[`src/format.hpp`](../src/format.hpp) と [`src/loader.cpp`](../src/loader.cpp)

元の重みから公開ファイルを作ったプログラムは [`tools/convert/`](../tools/convert/) にあります（2026 年 11 月 14 日に追加）。変換の方法は [TECHNOLOGY.ja.md](TECHNOLOGY.ja.md) の 3.2 に書いてあります（[9 章](#9-ファイルを書く)）。

## 1. 概要

ファイルは JSON のヘッダーと、ヘッダーが指すデータのブロックでできています。

重みの行列は数値のまま保存していません。次の 3 つで保存しています。

* **符号列**：重み 1 個あたり 3 bit か 4 bit
* **値の表**：数値の組が 4,096 個。行列ごとに 1 つ
* **倍率**：行ごとに 1 個

これらはすべて**回転した座標**での値です。符号にする前に、行列の行と列を符号つきのアダマール変換で混ぜています。符号（+1／-1）の列そのものは保存せず、それを作る種（seed）だけをヘッダーに書いています。

正規化の重みなどの小さなパラメーターは 16 bit の浮動小数点数のまま保存していて、**ベクトル**と呼びます。

整数はすべてリトルエンディアンです。

## 2. ファイルの配置

| 位置 | 大きさ | 内容 |
|---|---|---|
| 0 | 4 | 文字 `YSKN` |
| 4 | 4 | バージョン（符号なし 32 bit）：`1` |
| 8 | 8 | JSON ヘッダーのバイト数（符号なし 64 bit） |
| 16 | 8 | 最初のデータブロックの位置（符号なし 64 bit。参考情報） |
| 24 | 8 | ファイル全体のバイト数（符号なし 64 bit） |
| 32 | （上の長さ） | ヘッダー：JSON オブジェクト 1 個（UTF-8） |

ヘッダーの終わりから最初のデータブロックまではゼロで埋めてあります。データブロックの場所は、ヘッダーにある「ファイル先頭からの位置」で決まります。形式として整列の決まりはありません（公開ファイルでは、どのブロックも 256 バイトの倍数の位置から始まります）。

## 3. ヘッダー

JSON オブジェクトには `model`・`tensors`・`vectors` の 3 つがあります。

### 3.1 `model`

モデルの寸法（`arch`・`layers`・`hidden`・`ffn`・`heads`・`kv_heads`・`head_dim`・`vocab`・`eps`・`rope_theta`・`tie_embeddings`）、アーキテクチャごとの項目、そして `source`（元の重みの出どころ。公開モデルでは Hugging Face のリポジトリと版）です。テンソルを使ってモデルがどう計算するかは、元のモデルと、その `arch` 用のエンジンのソースが定めます。この文書が扱うのはテンソルの保存の仕方だけです。

### 3.2 `tensors`

リストです。1 つの項目が、`rows` 行 `cols` 列の行列 1 つを表します（`y = W x`。入力が `cols` 個、出力が `rows` 個）。

| 項目 | 意味 |
|---|---|
| `name` | 公開モデルでは、元のチェックポイントのパラメーター名を短くしたもの（6 章） |
| `role` | `body`、`head`（出口の行列）、`embedding`、`draft`（補助モデルの行列） |
| `rows`・`cols` | 形。`cols` は 512 の倍数 |
| `physical_rows` | 保存してある行数。省略時は `rows`。`rows` を超える行は詰め物 |
| `l` | 状態の bit 数。省略時は 12。この文書とエンジンが扱うのは 12 だけ |
| `d` | 1 歩あたりの重みの数。省略時は 2（この値だけ） |
| `t` | 1 つの系列の重みの数。省略時は 256（この値だけ） |
| `bits` | 1 歩あたりの bit 数。公開ファイルでは 6（重み 1 個あたり 3 bit）か 8（同 4 bit）。読み取り側は 4〜8 を受け付ける |
| `start` | `zero`（省略時）か `carry`（公開ファイルでは使っていない。この文書では定義しない） |
| `layout` | 符号列の並べ方。`warp`（省略時）か `row`（4.3） |
| `stream_off`・`stream_bytes` | 符号列 |
| `lut_off` | 値の表。半精度浮動小数点数 8,192 個（16,384 バイト） |
| `scale_off` | 倍率。半精度浮動小数点数 `physical_rows` 個 |
| `rot_in`・`rot_out` | 入力側（列）と出力側（行）の回転（3.3） |
| `rar` | `null`、またはタイルごとに bit 数を変えるための項目（公開ファイルでは使っていない。この文書では定義しない。`src/loader.cpp` を参照） |
| `bias_off`・`proxy`・`encoder` | 読み取り側は使わない。`bias_off` は 0、`proxy` は変換が記録した数値、`encoder` は文字列 |

「半精度浮動小数点数」は IEEE 754 binary16 です。

### 3.3 回転

`rot_in` と `rot_out` はオブジェクトです。

| 項目 | 意味 |
|---|---|
| `kind` | `H512`（4.5・4.6）。`rot_out` では `none` も可。`AYA` は別の種類で、公開ファイルでは使っておらず、この文書では定義しない |
| `m` | 512 個のブロックの数（`rot_in` は `cols / 512`、`rot_out` は `rows / 512`） |
| `sign_seed`・`sign_offset` | 符号の出どころ（4.5） |
| `rule` | `splitmix64`（省略時）か `mulberry32_7919_13` |
| `qm_off` | `AYA` だけが使う。それ以外は 0 |

`rot_out` が `null` か、種類が `none` なら、そのテンソルに出力側の回転はありません。項目を省いたファイルのための既定もあります（公開ファイルは必ず書いています）。`rot_in` が無ければ `H512`・種 7・オフセット 0・規則 `mulberry32_7919_13`。`rot_out` が無ければ、`head` と `embedding` は出力側の回転なし、それ以外は `H512`・種 7・オフセット `cols`・規則 `mulberry32_7919_13` です。

### 3.4 `vectors`

`{ "name", "off", "n", "dtype" }` のリストです。位置 `off` に 16 bit の数値が `n` 個あります。`dtype` は `f16`（省略時。半精度浮動小数点数）か `bf16`（bfloat16。IEEE 754 単精度の上位 16 bit。読むときは、その 16 bit を 32 bit 浮動小数点数の上半分に置き、下半分をゼロにする）です。

## 4. 行列を復元する

### 4.1 系列と歩

各行を、256 個の重みからなる**系列** `S = cols / 256` 個に分けます。1 つの系列は 128 **歩**で符号化され、1 歩で重み 2 個が決まり、符号を `bits` bit 使います。したがって 1 つの系列の符号は `128 * bits` bit、つまり 32 bit のワードが `W = 4 * bits` 個です。

系列の中の bit 番号 `p`（0 から）は、ワード `p div 32` の bit `p mod 32` です。ワードの bit 0 は最下位 bit です。

### 4.2 bit から値へ

歩 `j`（0〜127）について、`e = bits * (j + 1)` とします（この歩の bit が終わる位置）。この歩の**状態**は、そこで終わる 12 bit です。

    state = Σ（i = 0..11） b[e - 12 + i] × 2^i          （b[p] は系列の bit p。p < 0 のとき b[p] = 0）

つまり新しい bit ほど状態の上位にあり、1 歩ごとに古い bit が下へずれます。系列の先頭より前にはみ出すのは最初の 1 歩だけで、はみ出した部分の bit は 0 として扱います。

値の表には 4,096 組が入っています。歩 `j` で決まる値は

    v[2 j]     = table[2 × state]
    v[2 j + 1] = table[2 × state + 1]

で、これに行の倍率を掛けたものが、回転した座標での行列です。

    M[r][256 × s + k] = scale[r] × v[k]           （行 r、系列 s、k = 0..255）

状態は 1 つ前の状態と 12 - `bits` bit を共有するので、1 歩の値は 1 つ前の歩の bit にも左右されます。これがトレリス符号です。どんな bit 列も正しい符号です。

### 4.3 系列のワードの場所

`stream_off` の位置に、32 bit のワードが `physical_rows × S × W` 個あります。行 `r`・系列 `s` のワード `w`（0〜`W` - 1）は、次の番号のワードです。

* `row` の並び：`(r × S + s) × W + w`
* `warp` の並び：`q = s × physical_rows + r`、`g = q div 32`、`lane = q mod 32`、`c = w div 4` として
  `((g × bits + c) × 32 + lane) × 4 + (w mod 4)`

言葉で言うと、`warp` は系列を「系列 0 の全行、系列 1 の全行、…」の順に並べ、32 個ずつを 4 ワード（16 バイト）単位で交互に置いたものです。32 行を同時に復号する GPU の 32 スレッドが、隣り合ったメモリを読めるようにするためです。`warp` では `physical_rows × S` が 32 の倍数である必要があります（エンジンは行数が 64 の倍数であることを求めます）。

### 4.4 アダマール変換

`H` は 512 × 512 のアダマール行列（自然な順序、シルベスターの作り方）です。`a AND b` の 1 の bit の数が偶数なら `H[a][b] = +1`、奇数なら `-1`。係数 `1 / sqrt(512)` を掛けて使います。`H / sqrt(512)` は対称で、それ自身が逆行列です。長さが 512 の倍数のベクトルは、512 個ずつのブロックごとに変換します。

### 4.5 符号

`signs(rule, seed, offset, n)` は、終わりのない列の位置 `offset`〜`offset + n - 1` にある `+1`／`-1` の値 `n` 個です。64 bit と 32 bit の符号なし整数の演算（あふれは切り捨て）で、次のように決まります。

    splitmix64、位置 k（0 から）：
        z = seed + (k + 1) × 0x9E3779B97F4A7C15
        z = (z XOR (z >> 30)) × 0xBF58476D1CE4E5B9
        z = (z XOR (z >> 27)) × 0x94D049BB133111EB
        z = z XOR (z >> 31)
        z の最上位 bit が 1 なら +1、そうでなければ -1

    mulberry32_7919_13、位置 k（0 から）：
        s0 = (seed mod 2^32) × 7919 + 13            （これが 0 なら 0x9E3779B9）
        t = s0 + (k + 1) × 0x6D2B79F5
        t = (t XOR (t >> 15)) × (t OR 1)
        t = t XOR (t + (t XOR (t >> 7)) × (t OR 61))
        t = t XOR (t >> 14)
        t < 2^31 なら -1、そうでなければ +1

入力側は `s_in = signs(rot_in.rule, rot_in.sign_seed, rot_in.sign_offset, cols)`、出力側は `s_out = signs(rot_out.rule, rot_out.sign_seed, rot_out.sign_offset, physical_rows)` を使います。

### 4.6 元のモデルの座標に戻す

4.2 の `M` から、次のようにします。

1. 入力側（すべての行について）：行を `H / sqrt(512)` で変換し（512 列ずつ）、列 `i` に `s_in[i]` を掛ける。
2. 出力側（出力側の回転があるテンソルだけ。すべての列について）：列を `H / sqrt(512)` で変換し（512 行ずつ）、行 `n` に `s_out[n]` を掛ける。

結果の `W` が、このファイルが表す行列（元のモデルの座標）です。式で書くと、`D_in`・`D_out` を符号の対角行列、`Hn` をブロックごとの `H / sqrt(512)` として

    W = D_out × Hn × M × Hn × D_in          （出力側の回転が無ければ W = M × Hn × D_in）

エンジンは `W` を作りません。`y = W x` を、`x' = Hn (D_in x)`、`z = M x'`、`y = D_out (Hn z)` の順に、`M` を符号から直接取り出しながら計算します。

## 5. エンジンがしていること

形式の一部ではありませんが、復元した行列とエンジンの計算の小さな違いは、次の点から生じます。

* 行列（`body`・`head`・`draft`）では、エンジンはファイルを読み込むときに値の表を 8 bit に丸めます。`gamma =（表の絶対値の最大）/ 127`、`q = round(値 / gamma)`（-127〜127 に制限）とし、行 `r` の倍率を `scale[r] × gamma` にします。`yskn_decode.py --engine-table` は、この表で復元します。埋め込みは 16 bit の表のまま読みます。
* 行列への入力は、回転のあと、ベクトルごとに 1 つの倍率で 8 bit の整数に丸めます。積を整数で計算するためです（[TECHNOLOGY.ja.md](TECHNOLOGY.ja.md) の 4 章）。
* エンジンは読み込み時に、符号列を計算用の並びにもう一度並べ替えます（`src/repack.cu`）。意味は変わりません。

## 6. 公開しているファイル

| ファイル | テンソル | ベクトル |
|---|---|---|
| 品質モデル `qwen38_27b_quality.yskn` | `body` 400（1 歩 8 bit が 288、6 bit が 112）、`head`（8）、`embedding`（6） | 449 |
| 最速モデル `qwen38_27b_speed.yskn` | `body` 400（すべて 1 歩 6 bit）、`head`（8）、`embedding`（6） | 449 |
| 補助モデル `bdraft2_k8.yskn` | `draft` 46（1 歩 8 bit、出力側の回転なし） | 35 |

どれも `l` = 12、`start` = `zero`、種類 `H512`・規則 `mulberry32_7919_13`・種 7、行列は `warp`・埋め込みは `row` の並び、ベクトルは `bf16` です。`rar`・`AYA`・`carry` は使っていません。

名前は元のチェックポイント（`Qwen/Qwen3.8-27B`）に対応します。テンソルやベクトルの `layers.N.X` は、パラメーター `model.language_model.layers.N.X.weight`（元に `.weight` が無いものは `model.language_model.layers.N.X`）です。`embed_tokens` は `model.language_model.embed_tokens.weight`、`norm` は `model.language_model.norm.weight`、`lm_head` は `lm_head.weight` です。ベクトルには元のパラメーターの数値が元の順序のまま入っています（軸が複数あるパラメーターは 1 列に並べたもの）。元のチェックポイントのうち、`model.language_model.*` と `lm_head.weight` 以外のパラメーター（画像の部分 `model.visual.*` など）は、ファイルに入っていません。

## 7. 自分でファイルを確かめる

    python tools/yskn_decode.py info    qwen38_27b_quality.yskn
    python tools/yskn_decode.py compare qwen38_27b_quality.yskn --original <Qwen/Qwen3.8-27B の *.safetensors があるフォルダー> --json out.json
    python tools/yskn_decode.py decode  qwen38_27b_quality.yskn layers.3.self_attn.k_proj --out k_proj.npy

`compare` はすべてのテンソルを復元して元の重みと比べ、相対誤差 `|W_復元 - W_元| / |W_元|`（フロベニウスノルム）を表示します。ベクトルは、元の数値と 1 bit も違わないことを確かめます。元のチェックポイント（約 54 GB）が必要で、デスクトップの CPU で 30 分ほどかかります。

公開ファイルでの結果です（全テンソルの一覧は [`tools/records/`](../tools/records/) にあります）。

| モデル | テンソル | 重み 1 個あたりの bit | 相対誤差：中央値（最小〜最大） |
|---|---|---|---|
| 品質モデル | 本体の行列 288 個 | 4 | 0.092（0.085〜0.106） |
| 品質モデル | 本体の行列 112 個 | 3 | 0.177（0.166〜0.199） |
| 最速モデル | 本体の行列 400 個 | 3 | 0.177（0.163〜0.202） |
| 両方 | 出口の行列 | 4 | 0.087 |
| 両方 | 埋め込み | 3 | 0.146 |

どちらのモデルも、ベクトル 449 個すべてが元のチェックポイントの数値と 1 bit も違いません。

この大きさの相対誤差は、重み 1 個あたり 3〜4 bit なら普通の値です。これは「保存した重みが元の重みからどれだけ離れているか」であって、モデルの出力の良し悪しではありません。変換では、モデルの出力が元に近くなるように符号を選んでいます（[TECHNOLOGY.ja.md](TECHNOLOGY.ja.md) の 3.2）。これは、この数値を最小にすることとは別です。出力の品質は別に測っています（[MEASUREMENTS.ja.md](MEASUREMENTS.ja.md)）。

## 8. テストデータ

[`tools/testdata/tiny.yskn`](../tools/testdata/tiny.yskn)（468,304 バイト、SHA-256 `3f4a48866f6a1751beabc3b9a8d06088672a3db0aa0a4c3f96e1877cb448d393`）は、小さなテンソル 4 つとベクトル 2 つが入ったコンテナです。1 歩 6 bit と 8 bit、2 つの並び、2 つの符号の規則、出力側の回転のあり・なし、2 つのベクトルの型を含みます。モデルは入っていません。符号列・表・倍率は擬似乱数です。[`tools/yskn_fixture.py`](../tools/yskn_fixture.py) を実行すると、同じファイルが 1 バイトも違わずにできます。

[`tools/testdata/tiny_expected.json`](../tools/testdata/tiny_expected.json) には、読み取りプログラムが得るべき値が入っています。ヘッダーの数値、いくつかの符号の列の SHA-256（符号つき 1 バイトの列として）、そしてテンソルごとに、状態の SHA-256（符号なし 16 bit・リトルエンディアン、行 × 系列 × 128）、回転した座標での値の SHA-256（32 bit 浮動小数点数・リトルエンディアン、行 × 列。表の値と倍率をそれぞれ 32 bit 浮動小数点数に直してから掛けたもの）、決まった位置の重みの値、重みのフロベニウスノルムです。`python tools/yskn_decode.py selftest` は、このリポジトリの読み取りプログラムをこれと照合します。あわせて、4 章のとおりに 1 bit ずつ読む遅い処理で数行を読み直し、同じ値になることも確かめます。

## 9. ファイルを書く

書く側は、行列ごとに、値の表・行ごとの倍率・符号列を、復元した行列が保存したい行列に近くなるように作り、2〜4 章のとおりに並べます。どんな bit 列も正しい符号なので、`tools/yskn_fixture.py` は（役には立ちませんが）完全な書き込みプログラムです。符号列を擬似乱数で埋めています。

難しいのは良い符号を選ぶことです。公開ファイルを作ったプログラムと、それが使うデータは [`tools/convert/`](../tools/convert/) にあります。方法は [TECHNOLOGY.ja.md](TECHNOLOGY.ja.md) の 3.2 に書いてあります。公開ファイルを作った PC で変換し直すと、本体のすべての行列と埋め込みの符号が同じになり、出口の行列を公開ファイルから写すと、公開ファイルと 1 バイトも違わないファイルになりました。ほかの PC で同じ符号になるかは、その PC の計算の細部によります（[`tools/convert/README.md`](../tools/convert/README.md) の「What we got」と「Limits」）。
